2Freeze the garbage collector

The parsed save makes every full collection expensive

A parsed save is several million Python objects. Full garbage collections kept walking all of them. Calling gc.freeze() for the duration of an import removes that cost. It helps on master already, and more once the ORM churn is gone.

3Rewrite the Rust parser

Parser, one step at a time

The new parser is a hand-written single pass that builds Python objects directly and shares repeated strings. Its output equals the current parser's on all 110 saves, and 3 million random inputs gave the same result in both. The right column is peak memory for the largest save.

4Take the write path off the ORM

5Parse only what the import reads

Projection saves little, because the import reads almost everything

The import reads 37 top-level sections, 93.7% of the save's bytes. Skipping the rest gains about 4%. Filtering inside the big sections (ships, fleets, countries) would keep about a third of the values and roughly halve parse time again, but it needs a hand-maintained list of keys.

Also measured

More processes don't help a single game

The database stage of one game is serial, so the existing --threads option only moves parsing to worker processes, and pickling the result back costs more than it saves. Importing different games in separate processes does scale.

How this was measured

Method and caveats

  • Corpus: 110 autosaves from 4 AI observer games of Stellaris 4.5.2, about 6 GB of gamestate text in total.
  • 4-core cloud container. Every benchmark was pinned to its own core with taskset; comparisons were re-run under the same pinning.
  • Database equivalence: the ORM steps alone give byte-identical databases to master's on all four games, keys included. With the new parser as well, values match master within 1e-9 relative, which is also how far two runs of master differ from each other, because the current parser returns dicts in random order and float sums depend on that order. The new parser keeps file order, so its imports are repeatable.
  • Tests: the merged prototype passes 783 tests; the same 12 tests fail on unmodified master in this environment (no game localisation files, no test/saves).
  • Not done: a 110-save run of the parser benchmark on its own, the Core/raw-SQL rewrite, a database comparison under the nested projection.
  • Code and scripts: branch ccr-e1c741ee-k1l8sj, under tools/perf/. It is an evaluation branch, not one to merge.
